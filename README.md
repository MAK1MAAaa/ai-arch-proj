# 考古图志 · ArchSearch

本地运行的文化遗址检索与历史地图网页，当前包含3905项资料，支持现代与历史双图对照。

顶部检索，左侧“资料面板”可展开／收起、拖动调宽，“资料详情”打开弹窗。现代图叠加本地国界参考，两图保持同级缩放；定位遗址统一使用区域视图。历史图仅按明确单年联动，区间和未知年代保留背景，并醒目标明背景年不能作为遗址断代。

资料面板收起时，入口会显示检索结果数。全库目录中，无主图坐标、极区及固定地图范围内的资料可直接打开详情。分享链接中的遗址与阶段可以独立恢复，查询失败时保留对应提示。

顶部“筛选”按需展开地点类型与结果数；“模型”打开独立配置弹窗，关闭后返回地图，不占用常驻地图空间。手机端使用紧凑工具栏。

检索进度、取消和失败后的重试都在顶部检索区。等待时可继续编辑问题，改好后重新提交。首次语义检索可能需要加载本地模型。

地图的“图层与说明”集中提供底图切换、平移同步、图例与来源，默认收起。历史图直接显示实际背景年及其与所选遗址的关联；两张地图保持同时展示。

密集全库定位点以方框数字聚合，点击可分页选择资料或放大查看。选中遗址后周围定位点仍保持聚合，圆形编号用于显示检索排名。历史图择显可读的政权名称，点击疆域可核验完整名称与来源。

左侧“全库浏览”的国家／地区与来源分区会互相缩小选项。可选“拉丁美洲与加勒比”中的圭亚那，查看新增的堡垒、市场和岩刻资料。选择斯塔布鲁克市场，可对照市场大厅于1881年开放时的历史图。[本批来源与范围](src/archsearch/data/GUYANA-LICENSE.md)

在“全库浏览”选择“断代状态 → 已有来源阶段”，可集中查阅有年代证据的遗址。此条件只影响目录及双图的全库点位，可和地域、固定地图范围组合。

打开遗址详情后，点击“导出资料 JSON”可单独保存该遗址的来源、年代证据和实际显示的地图状态。从全库目录访问时也可直接导出。更新后重启本地服务即可使用。

“导出本次结果”保存最近一次成功检索的排名和实际地图视图。遗址、阶段、目录与定位附录按该次检索的语料版本核验，下载提示会列出省略的附录。

页面底部“使用说明与来源许可”默认收起，可分别展开使用方法、资料边界及来源许可。

## 日常启动

使用本地 Ollama 增强时，先打开 Ollama 程序，或在另一个终端运行 `ollama serve`；已经运行时无需重复启动。基础检索可以单独运行。在 Windows PowerShell 中执行：

```powershell
cd D:\Github\ai-arch-proj
uv run --no-sync archsearch serve
```

浏览器打开 **http://127.0.0.1:8000/**，运行状态见 **http://127.0.0.1:8000/api/status**。保持终端运行；按 `Ctrl+C` 停止，再执行启动命令即可重启。

## 首次安装或准备数据

需要 Python 3.12 和 uv。在仓库根目录执行：

```powershell
uv sync --locked --dev
uv run --no-sync archsearch prepare
uv run --no-sync archsearch prepare-history
uv run --no-sync archsearch serve
```

首次准备需联网下载固定版本的 E5 模型和历史地图数据；准备完成后，检索及历史地图可离线使用，现代 OSM 瓦片仍需联网。更新语料后重新运行 `prepare` 并重启服务；日常启动无需重复准备。

启动时按来源清单逐批校验资料。单次加载内复用内容相同的记录编码，以缩短启动等待。

E5 加载或编码期间仍可刷新运行状态和使用 BM25。同一次语义检索的原问题与扩展词使用同一份模型和向量。若检索期间发现这些文件已更新，稍后重试即可。同一目录的多个 `prepare` 会依次执行。

模型、索引及历史库默认保存在仓库根目录的 `.archsearch/`。基础检索无需 Node.js、pnpm 或 GPU；LLM 通过单独运行的 Ollama 或 API 服务提供。

## 当前检索模型

基础检索为本地 **`intfloat/multilingual-e5-small`**（CPU），可切换 **BM25**。启用 **LLM 增强**后，先改写查询，再融合本地检索排名；资料原文和地图位置不由模型生成。

关键词模式支持省略常见拉丁变音符号。例如用 `Goree` 查找 `Gorée`，结果和来源保留原始拼写。此更新可直接使用已有 E5 索引，重启服务后生效。

点击顶部“模型”，在弹窗中选择 Ollama，等待自动获取模型列表，选择本机已缓存的 **`qwen3.5:9b`** 并“应用所选模型”，勾选弹窗中的“LLM 增强”后关闭并检索。顶部显示增强开关状态；`qwen3.5:2b` 可作为速度优先的备选，应用只获取列表，不自动下载模型。

首次配置 API 且尚无 `.env` 时，将 [`.env.example`](.env.example) 复制为根目录 `.env`；已有文件直接编辑。填写 `base_url`、`api_keys` JSON 列表和 `model`，重启服务即可加载。多 Key 写成 `api_keys=["你的第一个Key","你的第二个Key"]`；真实 `.env` 不提交 Git。

LLM 启动配置有误时，基础检索和地图照常启动。终端与“模型”弹窗提供修复提示，也可在弹窗中先应用当前会话的模型。

也可在页面选择“OpenAI 兼容 API”，填写地址与密钥，自动获取模型列表后选择并应用。页面修改只保存在服务内存；重启会重新读取 `.env`。操作、Key 轮换及配置优先级见[LLM 增强说明](docs/llm-search.md)。

可直接试搜“寻找莎士比亚的坟墓”，选择结果后对照现代位置与1616年历史疆域。其他中文专名仍可能漏检，模型改写也可能误译；请核对实际检索词和来源原文。
